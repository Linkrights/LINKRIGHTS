# LINKRIGHTS 설계 문서

이 문서는 "왜 이렇게 만들었는가"를 기록한 것입니다.
나중에 다른 사람이 이어받거나, 기능을 추가할 때 먼저 읽어보세요.

---

## STEP 1. 전체 기술 구조

```
   [ 이용자의 휴대폰 / 컴퓨터 ]
              │
              ▼
   ┌───────────────────────────┐
   │  LINKRIGHTS 웹사이트       │   ← Vercel에 올라간 Next.js 사이트
   │  (미리 만들어 둔 정적 페이지) │
   └───────────────────────────┘
        │                    │
        │ 정보 탐색            │ AI 질문일 때만
        │ (비용 0원)           ▼
        │            ┌──────────────────┐
        │            │  /api/ask (서버)  │  ← OpenAI 키는 여기에만 있음
        │            └──────────────────┘
        │                    │
        ▼                    ▼
   content 폴더의 JSON     OpenAI API
   (권리정보 · 기관정보)
```

핵심 아이디어 3가지

1. **데이터베이스 서버가 없습니다.** 모든 글은 `content` 폴더의 JSON 파일입니다.
   → 월 고정비 0원, 백업은 GitHub이 알아서, 비전공자도 파일만 고치면 됩니다.
2. **AI는 꼭 필요한 순간에만 부릅니다.** 목록·검색·상세 페이지는 미리 만들어 둔 정적 페이지입니다.
3. **AI는 "제공된 자료 안에서만" 답합니다.** 서버가 답변을 한 번 더 검사해
   등록되지 않은 기관 id·전화번호·링크를 제거합니다.

## STEP 2. MVP에 넣은 것 / 나중으로 미룬 것

### 지금 만든 것 (B단계 MVP)

| 기능 | 상태 |
|---|---|
| LINKRIGHTS 소개 | ✅ `/about` |
| 분야별 권리·생활정보 (6개 분야, 14개 글) | ✅ `/rights` |
| 권리정보 탐색 | ✅ 분야 카드 + 목록 + 상세 |
| AI 기반 정보 안내 | ✅ `/ask` + `/api/ask` |
| 관련 기관 연결 (16곳) | ✅ `/organizations` |
| 프로그램 및 활동 소개 | ✅ `/programs` |
| 긴급상황 안내 | ✅ `/emergency` + AI 답변 앞 우선 표시 |
| 다국어 (한 · 영 · 중 · 베) | ✅ UI 4개 언어 + 콘텐츠 확장 구조 |
| 모바일 반응형 | ✅ 모바일 우선 설계 |
| 기본 SEO | ✅ 페이지별 메타데이터 · sitemap · robots · 구조화 데이터 |
| 개인정보 처리방침 | ✅ `/privacy` |

### 일부러 만들지 않은 것

| 기능 | 미룬 이유 |
|---|---|
| 회원가입 · 로그인 · 사용자 DB | 청소년 개인정보를 보관하는 순간 위험과 책임이 급증합니다. MVP에 필요 없습니다. |
| 커뮤니티 게시판 | 신고·차단·모니터링 체계 없이 열면 안전하지 않습니다. 지금은 "준비 중" 안내만 표시합니다. |
| 멘토 매칭 · 실시간 채팅 | 사람이 상시 대응해야 하는 기능입니다. 운영 인력이 확보된 뒤에 검토합니다. |
| 관리자 대시보드 | JSON 파일 + GitHub 웹 편집으로 충분합니다. 만들면 유지보수 대상만 늘어납니다. |
| 벡터 DB · RAG 인프라 | 콘텐츠가 수십 건 규모라 키워드 검색으로 충분하고, 비용과 복잡도만 늘어납니다. |

### 다음 단계에 검토할 것

1. 권리정보 30~50건으로 확대, 영어·중국어·베트남어 번역 순차 추가
2. 지역별 기관 정보 추가 (현재는 전국 단위 기관 위주)
3. 콘텐츠가 100건을 넘으면 검색 방식 개선 검토
4. 안전한 운영 체계를 갖춘 뒤 커뮤니티 기능 검토

## STEP 4. 폴더 구조

`README.md` 의 [13번](../README.md#13-폴더-구조)에 정리되어 있습니다.
한 문장으로 요약하면:

> **글은 `content/`, 화면 문구는 `messages/`, 코드는 `src/`.**
> 운영자는 앞의 두 폴더만 열면 됩니다.

## STEP 5. 데이터 구조

### 권리정보 (`content/rights/*.json`)

| 항목 | 뜻 | 왜 필요한가 |
|---|---|---|
| `id` | 글의 고유 이름 (= 파일 이름 = 주소) | 링크가 바뀌지 않게 하려고 |
| `category` | 분야 | 목록 분류 |
| `status` | `published` / `draft` | 준비 중인 글을 숨기려고 |
| `featured` | 홈에 먼저 보일지 | 자주 찾는 정보를 앞에 |
| `owner` | 담당자 | 누가 책임지는지 남기려고 |
| `reviewed_at` | 마지막 검토일 | **1년이 지나면 "검토 필요" 표시 + AI 근거에서 제외** |
| `keywords` | 검색·AI 매칭용 단어 | 사용자의 말과 글을 연결하려고 |
| `organizations` | 연결할 기관 id 목록 | **등록된 기관만 노출하려고** |
| `related` | 함께 보면 좋은 글 | 탐색을 이어가려고 |
| `sources` | 공식 출처 (제목 + URL) | 근거를 밝히려고 |
| `i18n.{언어}` | 언어별 본문 | 번역을 하나씩 늘려갈 수 있게 |

본문(`i18n.ko`)은 화면 구성과 1:1로 맞춰져 있습니다.

| 필드 | 화면에서 |
|---|---|
| `title`, `summary` | 제목과 한 줄 요약 |
| `situations` | ① 이런 상황인가요? |
| `rights` | ② 알아두어야 할 권리 |
| `actions` | ③ 이렇게 해보세요 (1, 2, 3 단계) |
| `organizations` (위) | ④ 도움받을 수 있는 곳 |
| `related` (위) | ⑤ 함께 보면 좋은 정보 |
| `note` | "확인해 주세요" 안내 상자 |

### 기관 (`content/organizations.json`)

`id / category / emergency / name / description / phone / website / languages / region / hours / status / owner / reviewed_at / source_url`

→ **이 파일이 사이트에서 전화번호가 나올 수 있는 유일한 출처입니다.**

### 긴급 설정 (`content/emergency.json`)

`keywords`(언어별 감지 단어) · `organizations`(긴급 연락처 id) · `title` · `message` · `steps` · `note`

→ 긴급 여부를 AI가 판단하지 않습니다. **검토된 키워드 목록**으로 먼저 확인합니다.

## STEP 6. UI/UX 설계 방향

### 기준

- **모바일 우선.** 모든 화면을 좁은 폭에서 먼저 설계했습니다.
- **긴 글 대신 카드와 단계.** 법조문 인용 대신 "이런 상황인가요? → 이렇게 해보세요" 흐름.
- **첫 화면에서 두 가지 길.** ① AI에게 질문하기 ② 분야 카드로 직접 찾기.
- **주체적인 표현.** "도움을 받아야 하는 사람"이 아니라 "권리를 알고 선택하는 사람"으로 씁니다.

### 색

| 역할 | 색 | 의미 |
|---|---|---|
| 메인 | 파랑 `#1f4fc4` 계열 | 공공기관의 신뢰감. 단, 짙은 남색보다 밝게 해 딱딱함을 줄임 |
| 포인트 | 로즈 `#d6417e` | SDG 10의 색에서 가져온 따뜻한 강조색 |
| 배경 | 흰색 / 아주 옅은 파랑 `#f5f8fd` | 밝고 깨끗하게 |
| 긴급 | 빨강 `#c62828` | 일반 안내와 확실히 구분 |
| SDG 배지 | `#c5192d`(SDG4), `#dd1367`(SDG10) | UN 공식 색은 배지에만 사용 |

색은 전부 `src/app/globals.css` 위쪽 `@theme` 안에 모여 있습니다. 거기만 고치면 사이트 전체 색이 바뀝니다.

### 접근성

- 본문 글자 16px 이상, 줄 간격 1.65
- 버튼 최소 높이 48px (손가락으로 누르기 쉽게)
- 키보드 이동 시 파란 테두리 표시, "본문 바로가기" 링크 제공
- 색만으로 정보를 전달하지 않음 (긴급 = 색 + 아이콘 + 글자)
- `word-break: keep-all` 로 한국어 단어가 어색하게 끊기지 않게 처리

## STEP 7. 기술 스택 확정과 이유

| 결정 | 선택 | 이유 | 검토했지만 고르지 않은 것 |
|---|---|---|---|
| 프레임워크 | **Next.js (App Router)** | SEO에 강한 정적 생성 + API 키를 안전하게 숨길 서버 기능을 하나로 제공 | 순수 React(SEO 약함), WordPress(서버 비용·보안 관리 필요) |
| 언어 | **TypeScript** | 콘텐츠 구조가 어긋나면 배포 전에 오류로 알려줌 | JavaScript (실수를 늦게 발견) |
| 스타일 | **Tailwind CSS v4** | 색·간격을 한 파일에서 관리, 모바일 대응이 쉬움 | 별도 CSS 파일 (관리 지점이 흩어짐) |
| 콘텐츠 | **JSON 파일 + GitHub 웹 편집** | 고정비 0원, 백업 자동, 되돌리기 가능 | Headless CMS(월 비용·계정 관리), Markdown(단계별 목록 구조에 부적합) |
| 배포 | **Vercel** | Next.js에 최적화, 파일을 올리면 자동 배포, 이 규모에서는 무료 | 자체 서버 (관리자 필요) |
| AI 연결 | **fetch로 OpenAI REST 직접 호출** | 라이브러리 버전 문제 없음, 코드가 한 파일에만 있음 | openai SDK (의존성 하나 더 늘어남) |
| 검색 | **키워드 점수 방식** | 콘텐츠 수십 건 규모에 충분하고 비용 0원, 결과 이유를 설명할 수 있음 | 벡터 DB (월 비용 + 복잡도) |
| 다국어 | **`[locale]` 주소 + messages JSON** | 라이브러리 없이 단순, 언어 추가가 파일 하나 | next-intl (설정이 많아 비전공자에게 부담) |

### 콘텐츠 수정 방식 (하나로 확정)

> **JSON 파일을 GitHub 웹에서 직접 편집합니다.**

- 프로그램 설치 없이 브라우저만으로 수정 가능
- 저장하면 Vercel이 자동으로 사이트를 갱신
- 잘못 고쳐도 GitHub에서 이전 버전으로 되돌릴 수 있음
- 배포 전에 `npm run check` 가 자동 실행되어, 형식이 틀리면 **사이트가 망가지기 전에** 막아줌

## AI 안전 장치 요약

| 위험 | 대응 |
|---|---|
| 없는 기관·전화번호를 지어냄 | AI는 **기관 id만** 반환. 실제 이름·번호는 서버가 `organizations.json`에서 채움. 본문에 섞인 미등록 번호·링크는 서버가 삭제 |
| 근거 없는 법률 정보 단정 | 등록된 권리정보만 참고자료로 전달. 근거가 없으면 "확인이 더 필요한 부분"에 명시 |
| 비자 승인 보장 · 의료 진단 | 시스템 규칙으로 금지 + 각 글의 `note`에 확인 안내 |
| 긴급상황에 일반 답변만 제공 | 키워드 감지 시 **AI를 부르지 않고** 검토된 긴급 카드를 즉시 표시 |
| 오래된 정보 사용 | 검토일이 1년 넘은 글은 AI 근거에서 제외하고 화면에 "검토 필요" 표시 |
| 비용 폭증 | 질문 길이 제한 · 참고자료 4건 제한 · 응답 길이 제한 · 5분/하루 사용량 제한 · OpenAI 하드 리밋 |
| 개인정보 입력 | 입력창 위에 경고 표시, 저장하지 않음, 개인정보 처리방침 공개 |
| API 키 노출 | 서버 전용 코드(`/api/ask`)에서만 사용. 브라우저로 전달되지 않음 |
